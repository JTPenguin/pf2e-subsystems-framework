# Follow-ups from the items run (2026-11-09)

Minor issues found while building the open items. None blocked the work. Each line names the item it came from.

- **progress-bar-and-thresholds:** Reset catches errors while restoring the baseline but not while saving it. A damaged baseline (say, from a hand-edited import) holding a bad `reveal` value would make Reset fail validation (`run.js` around line 104). Very unlikely.
- **thresholds-player-card:** a fully revealed threshold with empty player text shows only its points on the panel. Fine as is, or it could fall back to "???".
- **challenge-overlay-draggable:** a player can drag the panel over the sidebar, chat or hotbar; it is only kept on screen, not clear of Foundry's UI. Not checked: a UI scale other than 1 in a real client setting, and touch input.
- **panel-resize-corner-handle:** when the panel scrolls, its corner handle sits just left of the scrollbar, not in the very corner. Not checked: a UI scale other than 1, and touch input. The reset button's label is now "Reset position and size".
- **gm-window-compact-layout:** the End/Reset trap is gone (move-panel-start-end-controls-right, 2026-11-10): after End, Reset redraws at the far right, not on End's spot. A smaller one remains: after Start, Hide Panel redraws on Start's spot, so a quick second click hides the panel (Show Panel brings it back). Also: "Performance" is cut to "Performa…" in a 3-column grid at 760px.
- **hidden-vs-revealed-styling:** points-only (8% fill) vs full (16%) is the softest step in the dark theme; raise the numbers if it's hard to read at the table. On a hidden modifier only the name is italic, not its player text (as before). Light theme not checked live.
- **modifier-edit-window:** Add entry now opens the new modifier's window straight away (a blank entry has no other way to be edited). Say if you'd rather it didn't. Also: if two GM clients edit different effects of the same modifier at once, the last save wins; a note effect with no text leaves a stray "; " on the sheet (older bug).
- **gm-window-monster-style:** **your call:** the GM window (and the modifier window) now defaults to the light parchment theme to match PF2e's NPC sheets. Before, it followed Foundry's dark theme. A theme picked for the sheet in Configure Sheet still wins. The orange eye icon on parchment is fixed: it is dark red in the light theme (2026-11-10). A dark per-sheet theme was not checked live.
- **chip-toggle-detached-window:** not checked in a real Foundry popout: the browser pane opens the popout in the same tab, so the check moved the sheet into a same-origin iframe instead, as Foundry's detach does. Worth one click in a real detached window at the next session.
- **remove-panel-roll-button-tooltips (2026-11-10):** with several NPCs on the panel, a very long NPC name is cut off after two lines, and the removed tooltip was the only way to read the rest. The test names fit.
- **on-off-indicator / hidden-faded (2026-11-10):** Spent is still dimmed on the panel (it has no hidden state there) but no longer in the GM window. A hidden card fades as a whole, buttons included, so the eye that reveals a hidden skill looks faint; lift the buttons to full strength if that confuses. Off + hidden is the softest mix; raise `--ssm-hidden-opacity` (0.6) if it is hard to read at the table.
- **discovery-rolls-secret (2026-11-10):** **your call:** the GM's own Discovery roll from the GM window is a GM-only whisper, so players don't see that a roll was made (PF2e's Recall Knowledge does the same). Say if you want players to see a "???" card instead. Also: the world setting Show Secret Checks makes Discovery rolls public again, and a player can still pick another roll mode in PF2e's roll dialog. Links posted before this change roll in the clicker's own mode.
- **gm-panel-onoff-icon-button (2026-11-10):** in the GM window, Off and Spent now differ only by icon (a check vs a rotate-back arrow); the old struck-out "Spent" word is gone. If that is too subtle at the table, dim the Spent button or give Off its own icon.
- **panel-card-gm-label-on-hover (2026-11-10):** the player text now shows only on hover, so a keyboard or screen-reader user can no longer read it on the panel (Foundry's tooltip opens on pointer hover only). If that matters at your table, give each card an `aria-description` with the same text.
- **panel-fade-inactive-modifiers (2026-11-10):** the GM's hover highlight on a faded (Off or Spent) panel card is faint, because it fades with the card. If that is hard to see, lift faded cards to about 70% on hover.
- **panel-resize-corner-handle (2026-11-10):** a plain click on the resize handle, with no drag, still fixes the panel at its current size, so it stops growing with its content until Reset. Skip the save when nothing moved if that gets in the way.
- **remove-premise-field (2026-11-12):** `items/description-field-affordance.md` line 36 still says "[[remove-premise-field]] removes it"; fine as history, but reword it if that note is edited. The skill's `build_challenge.py` still writes `pins.sidebar: "premise"` for the old PF2e Subsystems module; left as is.
- **description-field-affordance (2026-11-12):** the empty description box opens by mouse only; Tab cannot reach it, as Foundry hides its edit button until hover. If keyboard use matters, give the empty box `tabindex="0"` and open it on Enter or Space.
- **reorder-by-dragging-header (2026-11-12):** the drop line on a hidden (faded) modifier or counter fades with it, and there is no keyboard way to reorder. A real mouse drag could not be driven in the browser pane, so the live check used dispatched drag events; the redraw after a drop relies on the browser firing `pointercancel` when a drag starts (Chrome and Firefox do).
